# MagicCode Super-Resolution（MagicSR）用户使用说明书

版本：v1.1.3  
适用：Native SDK / Unity 插件 / Unreal Engine 插件  
平台：Android（Vulkan / OpenGLES）、iOS / macOS（Metal）、Windows（OpenGL）

English: [`User_Guide.md`](User_Guide.md)

---

## 1. 产品简介

MagicSR 是 MagicCode 超分辨率 SDK，可将输入的 GPU 纹理放大并增强细节，适用于游戏画面、相机预览、UI 纹理等场景。

**推荐接入方式**（两步即可）：

1. `Enable`：输入一张 GPU 纹理，返回超分后的输出纹理  
2. `Disable`：结束使用时释放内部会话与输出纹理  

无需手动创建会话、选择后端或配置输入类型；这些由 `Enable` 内部自动完成。

| 层级 | 公开 API |
|------|----------|
| Native | `MC_Enable` / `MC_Disable` |
| Unity | `MagicSR.Enable` / `MagicSR.Disable` |
| Unreal | `UMagicSRBlueprintLibrary::Enable` / `Disable` |

插件公开 API 是对 Native `MC_Enable` / `MC_Disable` 的薄封装，业务代码应调用插件 API，而不是直接调用 `MC_*`。

### 1.1 Native 交付物：两条集成路径

Native SDK 提供**两套**静态库。请只选**一条**路径，不要混用：

| 路径 | 适用对象 | 链接 | 头文件 | 调用 |
|------|----------|------|--------|------|
| **简易路径（推荐）** | 多数应用 / 游戏 / 相机 | `libmagic_sr_enable.a`（核心 + Enable） | `mc_enable.h` | `MC_Enable*` / `MC_Disable` |
| **专业 / 进阶路径** | 需显式控制会话、后端或 CPU Buffer | `libmagic_sr.a`（仅核心） | `mc_interface.h` | `MC_Init` / `MC_Process` / `MC_Uninit` |

| 内容 | 简易路径 | 专业 / 进阶路径 |
|------|----------|-----------------|
| 头文件 | `interface/mc_enable.h` | `interface/mc_interface.h` |
| Android 库 | `lib/android/libmagic_sr_enable.a` | `lib/android/libmagic_sr.a` |
| iOS 库 | `lib/ios/libmagic_sr_enable.a` | `lib/ios/libmagic_sr.a` |

说明：

- 简易路径：**不必**再把 `mc_enable.c` 加入 App 编译；Enable 已包含在 `libmagic_sr_enable.a` 中。  
- 仅核心的 `libmagic_sr.a` **不**导出 `MC_Enable*`——只链它会导致 Enable 相关符号未定义。  
- **Unity / Unreal 插件**：Enable 已编进插件二进制；游戏侧无需直接链接上述 `.a`。  
- **Native 应用**：按上表选一条路径（见 §5.3）；Apple 仍需链接 Metal / MetalKit 等系统框架。

## 2. 快速开始

### 2.1 Unity

```csharp
using MagicSR.UnityPlugin;
using UnityEngine;

public class MyUpscale : MonoBehaviour
{
    public RenderTexture inputRT;   // RGBA8 输入
    public float scale = 2.0f;

    void Start()
    {
        // 建议：把模型目录设为可读写路径（见 §4 模型表）
        MagicSR.SetModelDir(Application.persistentDataPath + "/MagicSRModels");
    }

    void OnRenderImage(RenderTexture src, RenderTexture dst)
    {
        // 每帧：超分一帧（scale/尺寸不变时会自动复用会话）
        System.IntPtr outNative = MagicSR.Enable(src, scale);
        if (outNative == System.IntPtr.Zero)
        {
            Graphics.Blit(src, dst);
            return;
        }

        // 用输出 native 纹理创建/更新外部 Texture 再 blit（参见 MagicSRCameraUpscaler）
        // ...
        Graphics.Blit(src, dst); // 示例占位
    }

    void OnDestroy()
    {
        MagicSR.Disable(); // 唯一合法的释放方式
    }
}
```

也可直接传 native 指针：

```csharp
IntPtr outPtr = MagicSR.Enable(inputRT.GetNativeTexturePtr(), 2.0f);
MagicSR.Disable();
```

可选：`Enable_3params` / `Enable_4params` 指定模式 / 后端。

内置相机示例：挂载 `MagicSRCameraUpscaler`（Built-in 管线 `OnRenderImage` → `Enable`）。

### 2.2 Unreal Engine（C++）

```cpp
#include "MagicSRBlueprintLibrary.h"

// 每帧（或输入就绪时）
int64 OutNativeTex = UMagicSRBlueprintLibrary::Enable(InputNativeTexture, /*Scale=*/2.0f);
if (OutNativeTex == 0)
{
    // 失败处理
}

// 可选：Enable_3params / Enable_4params / SetInputSizeHint（Android Vulkan）

// 结束时
UMagicSRBlueprintLibrary::Disable();
```

Blueprint：`MagicSR | Easy` → **Enable** / **Enable_3params** / **Enable_4params** / **Disable**。

`InputNativeTexture` 为 native GPU 句柄（`int64`）：

| 后端 | 传入内容 |
|------|----------|
| Metal | `MTLTexture*` 指针转 `int64` |
| OpenGLES | `GLuint` 纹理 ID 转 `int64` |
| Vulkan | `VulkanTexture*` / 指向 `VkImage` 的指针转 `int64` |

### 2.3 Native C

调用 `MC_Enable` 前，链接 `libmagic_sr_enable.a` 并 `#include "mc_enable.h"`。详见 §1.1、§5.3。

```c
#include "mc_enable.h"

void* out = MC_Enable(input_texture, 2.0f);  // RGBA GPU 纹理
if (out == NULL) { /* 失败 — 查看日志 [MagicSR][Enable] err=<code> */ }

/* 使用 out（借出指针，不要 free / CFRelease / glDelete） */

MC_Disable(NULL);  // 或 MC_Disable(out)；参数可忽略

/* 可选：指定模式 / 后端 */
/* void* out = MC_Enable_3params(input_texture, 2.0f, HIGH_SPEED_MODE); */
/* void* out = MC_Enable_4params(input_texture, 2.0f, HIGH_SPEED_MODE, MAGIC_BACKEND_DEFAULT); */
```

## 3. Enable 行为说明

| 项目 | 说明 |
|------|------|
| 功能 | 懒初始化会话 + 处理一帧 + 返回输出 GPU 纹理 |
| `scale` | `float`，范围 `[1.0, 8.0]`；`<= 0` 时默认为 `2.0` |
| 会话复用 | 相同 `scale`、输入宽高、mode、backend 时复用内部会话与输出纹理 |
| 返回值 | 输出纹理指针；失败为 `NULL` / `IntPtr.Zero` / `0` |
| 所有权 | 输出由库持有，**只能**通过 `Disable` 释放 |

### 3.1 输入纹理格式（重要）

`Enable` 统一要求 **RGBA 系** GPU 纹理：

| 平台 / 后端 | 输入格式 | `Enable` 后端 |
|-------------|----------|----------------|
| iOS / macOS Metal | `RGBA8Unorm`（`MTLTexture*`） | Metal |
| Windows OpenGL | `RGBA8`（`GLuint` 转 `void*`） | OpenGL |
| Android OpenGLES | `RGBA8`（`GLuint` 转 `void*`） | OpenGLES |
| Android Vulkan | `RGB8Unorm` / `RGBA8` | Vulkan |

Unity 示例：使用 `GraphicsFormat.R8G8B8A8_UNorm` 的 `RenderTexture`。  
不要再向 `Enable` 传入 R8 单通道纹理。

### 3.2 尺寸 Hint（Android GLES / Vulkan — 必需）

在 **Android OpenGLES** 与 **Android Vulkan** 上，SDK 无法可靠查询输入纹理尺寸。调用 `Enable` 前**必须**先调用 `SetInputSizeHint` / `MC_Enable_SetInputSizeHint(width, height)`。未设置有效 hint（宽高需在 `[64, 4032]`）时，`Enable` 失败并返回 `MC_ENABLE_ERROR_SIZE_HINT_REQUIRED`（`-300006`）。

Unity 的 `Enable(Texture, scale)` 会根据 `Texture` 尺寸自动设置 hint；原生指针 / Native / UE 路径需自行设置。

Metal、Windows OpenGL 通常可查询尺寸，hint 可选。

### 3.3 尺寸与性能提示

- 输入宽高必须在 `[64, 4032]`。  
- `scale` / 尺寸频繁变化会触发重建，影响性能。  
- 失败时请查看日志中的 `[MagicSR][Enable] err=<code>`（见 `mc_enable.h` 中 `MC_ENABLE_ERROR_*`）。

## 4. 模型文件

多数场景不必手拷模型：先跑安装脚本，再按平台做极少几步即可。

### 4.0 一键放置模型（推荐）

在仓库根目录执行：

```bash
# macOS / Linux
./tools/setup_models.sh demo          # Android + iOS demo
./tools/setup_models.sh local         # 放到 <repo>/MagicSRModels（再 SetModelDir）
./tools/setup_models.sh unity --project /path/to/YourUnityProject
./tools/setup_models.sh ue --project /path/to/YourUEProject
./tools/setup_models.sh adb           # 推送到手机 Documents/MagicSRModels
```

```bat
REM Windows
tools\setup_models.bat demo
tools\setup_models.bat unity --project C:\path\to\YourUnityProject
tools\setup_models.bat ue --project C:\path\to\YourUEProject
```

脚本会把 `model/` 下 Enable 用的 GPU `.bin` 拷到对应目录。完整命令见 `./tools/setup_models.sh --help`。

### 4.1 用代码设置模型路径（推荐 API）

在 `Enable` **之前**调用：

| 层 | 单个 `.bin` 文件 | 模型目录 |
|----|------------------|----------|
| Native | `MC_Enable_SetModelPath("/abs/path/model.bin")` | `MC_Enable_SetModelDir("/abs/path/MagicSRModels")` |
| Unity | `MagicSR.SetModelPath(path)` | `MagicSR.SetModelDir(dir)` |
| Unreal | `SetModelPath(Path)` | `SetModelDir(Dir)` |

`SetModelPath` 优先于 `SetModelDir`。传空/NULL 可清除。不要用环境变量设置模型路径。

`SetModelDir` 会在该目录下**递归**查找 §4.3 中的默认文件名（最多 4 层），不会按任意 `.bin` 名乱扫。


### 4.2 脚本之后（按平台）

**Unity（推荐）**

1. 执行 `./tools/setup_models.sh unity --project <YourUnityProject>`  
   （写入 `Assets/StreamingAssets/MagicSRModels/`）  
2. 运行时把 StreamingAssets 拷到可写目录，并调用：

```csharp
MagicSR.SetModelDir(Application.persistentDataPath + "/MagicSRModels");
// 或: MagicSR.SetModelPath(某个bin的完整路径);
```

**Unreal（推荐）**

1. 执行 `./tools/setup_models.sh ue --project <YourUEProject>`  
   （写入 `Content/MagicSRModels/` 供打包）  
2. 运行时 `Enable` **不会**自动读 UE `Content/`。真机可先 `./tools/setup_models.sh adb`，或自行拷贝后：

```cpp
UMagicSRBlueprintLibrary::SetModelDir(TEXT("/storage/emulated/0/Documents/MagicSRModels"));
// 或单个文件：
// UMagicSRBlueprintLibrary::SetModelPath(TEXT("/storage/emulated/0/Documents/MagicSRModels/magic_vulkan_highspeed_gpu_params.bin"));
```

| 目标平台 | 当前可用的具体运行时路径 |
|----------|--------------------------|
| Android | `/storage/emulated/0/Documents/MagicSRModels/<model>.bin`（也支持 `/sdcard/Documents/MagicSRModels/`） |
| iOS | 应用沙箱 / Bundle 下的 `<model>.bin`，再 `MC_Enable_SetModelPath(fullPath)`（与 demo 一致） |

移动端**不要**只依赖相对路径 `MagicSRModels/`——它相对的是进程工作目录，打包后常常不是你以为的位置。

**Native（推荐）**

1. `./tools/setup_models.sh local` 或 `dir --dest <path>`（Android 真机可用 `adb`）  
2. 在 `MC_Enable` 之前用代码设置路径：

```c
/* 推荐：指向某一个 .bin 的完整路径 */
MC_Enable_SetModelPath("/absolute/path/to/magic_gles_highspeed_gpu_params.bin");

/* 或：指向含默认文件名的目录 */
MC_Enable_SetModelDir("/absolute/path/to/MagicSRModels");
```

| 平台 | 实用绝对路径 |
|------|----------------|
| Android | 应用 `filesDir` / 从 assets 解压出的路径；或 `/storage/emulated/0/Documents/MagicSRModels/` |
| iOS | Bundle 资源路径，或沙箱 `Documents/...`（见 `demo/ios`） |
| Windows | 如 `C:\\YourApp\\MagicSRModels\\magic_gl_highspeed_gpu_params.bin` |
| macOS | App 资源目录 / 安装目录下的绝对路径 |

相对搜索（`./MagicSRModels/`、`./<name>.bin`）只有在进程 cwd 恰好是该目录时才有效——适合本地工具，不适合正式发版应用。

### 4.3 平台 × 后端 × 默认模型名

| 平台 | 后端 | HighSpeed（`HIGH_SPEED_MODE`） | Speed（`SPEED_MODE`） |
|------|------|--------------------------------|------------------------|
| iOS / macOS | Metal | `magic_metal_highspeed_gpu_params.bin` | `magic_metal_speed_gpu_params.bin` |
| Windows | OpenGL | `magic_gl_highspeed_gpu_params.bin` | `magic_gl_speed_gpu_params.bin` |
| Android | OpenGLES | `magic_gles_highspeed_gpu_params.bin` | `magic_gles_speed_gpu_params.bin` |
| Android | Vulkan | `magic_vulkan_highspeed_gpu_params.bin` | `magic_vulkan_speed_gpu_params.bin` |

仍兼容旧别名：`magic_veryfast_gpu_params.bin`、`magic_veryfast_gles_params.bin`、`magic_highspeed_gpu_params.bin`。

### 4.4 `Enable` 如何查找模型（参考）

内部搜索顺序（用 §4.1 API）：

1. `MC_Enable_SetModelPath` / `MagicSR.SetModelPath` / UE `SetModelPath`  
2. 对 §4.3 中的每个默认文件名：  
   - `SetModelDir` 目录树 / `<name>`（递归，深度 ≤ 4）  
   - `MagicSRModels/<name>`  
   - `./<name>`  
   - Android：`Documents/MagicSRModels` 及相关路径  
3. iOS / macOS：App Bundle 查找  

找不到模型时，`Enable` 失败并返回 `MC_ENABLE_ERROR_MODEL_NOT_FOUND`（`-300009`）。

## 5. 集成步骤

### 5.1 Unity

1. 引入 C# 脚本：`plugin/unity/CSharp/`（至少 `MagicSR.cs`、`MagicSRNative.cs`）  
2. 构建并放入 Native 插件：  
   - Android：`libmagic_sr_unity.so` → `Assets/Plugins/Android/`  
   - iOS：`libmagic_sr_unity_ios.a` → `Assets/Plugins/iOS/`  
3. 放入模型到 `StreamingAssets/MagicSRModels/`  
4. 调用 `MagicSR.SetModelDir`（推荐）→ `Enable` → `Disable`

构建脚本参考：

- `plugin/unity/Native/build_android.sh`  
- `plugin/unity/Native/build_ios.sh`  
- 样例工程：`plugin/unity/Samples/AndroidSmokeTest/`

### 5.2 Unreal Engine

1. 复制插件到工程：`<YourProject>/Plugins/MagicSR`  
2. 确保已链接发布库：  
   - `release/v1.1/lib/android/libmagic_sr.a`  
   - `release/v1.1/lib/ios/libmagic_sr.a`  
3. 在 `.uproject` 中启用 MagicSR，重新生成工程 / 打开编辑器  
4. Blueprint 或 C++ 调用 `Enable` / `Disable`  
5. 放入模型：`Content/MagicSRModels/`

样例工程：`plugin/ue/Samples/AndroidSmokeTest/`

### 5.3 Native

按 §1.1 只选**一条**路径。

#### A. 简易路径（推荐）— Enable API

链接 `libmagic_sr_enable.a` + 引入 `mc_enable.h`。无需自行编译 `mc_enable.c`。

1. 头文件：`interface/mc_enable.h`  
2. 链接合并库：  
   - Android：`lib/android/libmagic_sr_enable.a`  
   - iOS：`lib/ios/libmagic_sr_enable.a`  
3. iOS 还需链接 Metal / MetalKit 等相关系统框架  
4. 调用 `MC_Enable_SetModelPath` / `MC_Enable_SetModelDir`（推荐）→ `MC_Enable` / `MC_Disable`

Android NDK / CMake 示例：

```cmake
add_library(my_app SHARED native-lib.cpp)
add_library(magic_sr_enable STATIC IMPORTED)
set_target_properties(magic_sr_enable PROPERTIES
  IMPORTED_LOCATION ${MAGIC_SR_ROOT}/lib/android/libmagic_sr_enable.a)
target_link_libraries(my_app magic_sr_enable ...)
```

iOS Xcode 示例：链接 `-lmagic_sr_enable`（搜索路径指向 `lib/ios/`），**不要**把 `mc_enable.c` / `mc_enable_metal.m` 加入 Compile Sources。

#### B. 专业 / 进阶路径 — 会话 API

链接仅核心库 `libmagic_sr.a` + 引入 `mc_interface.h`。不使用 Enable，走会话 API：

1. 头文件：`interface/mc_interface.h`  
2. 链接：`lib/android/libmagic_sr.a` 或 `lib/ios/libmagic_sr.a`  
3. 调用 `MC_Init` → `MC_Process` → `MC_Uninit`（见 §7）

## 6. 内存与生命周期（必读）

1. **`Enable` 返回的输出纹理是借出（borrowed）指针**  
   - 不要 `free` / `delete` / `CFRelease` / `glDeleteTextures` / `DestroyImmediate`  
   - iOS Metal：错误 `CFRelease` 会在释放点直接 `abort`  
2. **唯一合法释放方式是 `Disable()`**  
3. `Disable` 之后，此前返回的输出指针全部失效，不可再使用  
4. 可反复 `Enable`；在 `scale` 与尺寸不变时会复用内部资源  
5. `Disable` 后再次 `Enable` 会重新创建会话

## 7. 进阶 API（可选）

若需要显式控制输入/输出纹理、后端或 CPU Buffer 路径，请走 **专业 / 进阶路径**（§1.1 B）：链接 `libmagic_sr.a`，引入 `mc_interface.h`，并调用会话式 API：

| 平台 | API |
|------|-----|
| Native | `MC_Init` / `MC_Process` / `MC_Uninit` |
| Unity | `MagicSRSession.CreateEx` + `ProcessTexture` |
| Unreal | `CreateSessionEx` + `ProcessUTexture` / `ProcessNativeTexture` |

`InputType` / `Backend` 取值见 `mc_interface.h`。  
**普通游戏 / 相机接入优先使用简易 Enable 路径（`libmagic_sr_enable.a` + `mc_enable.h`），无需会话 API。**

更细的插件说明（英文）：

- `plugin/unity/USAGE_GUIDE.md`  
- `plugin/ue/USAGE_GUIDE.md`

## 8. 常见问题

**Q: Enable 返回空指针？**  
A: 查看日志 `[MagicSR][Enable] err=<code>`。常见原因：找不到模型（`-300009`）、Android 未设 size hint（`-300006`）、尺寸非法（`-300008`）、或 `MC_Init` / `MC_Process` 失败。同时确认 RGBA 输入与 `SetModelDir` / 模型路径。

**Q: 为什么 iOS 不能再用 R8？**  
A: 当前 `MC_Enable` 默认输入为 RGBA。R8 仅适用于旧的会话式 Metal/GLES 高级路径，不适用于 `Enable`。

**Q: 输出花屏 / 全黑？**  
A: 确认输入为 RGBA8、未对输出做非法释放，以及（Android GLES/Vulkan）`SetInputSizeHint` 与真实纹理尺寸一致；查看日志错误码。

**Q: 相机 / URP / HDRP 怎么接？**  
A: 将画面 resolve / blit 到一张 RGBA `RenderTexture`（或等价 native 纹理），再调用同一个 `Enable(texture, scale)`。无专用 Camera Enable API。

**Q: UE 里的 `EnableNative(scale, texture)` 还能用吗？**  
A: 已废弃。仍可调用，但参数顺序是旧的 **scale 在前**。请改用 `Enable(InputNativeTexture, Scale)`。

**Q: 可以多实例同时 Enable 吗？**  
A: `Enable` 路径是进程内单例。多路并发请改用会话式 API，或串行共享同一 `Enable` 会话。

**Q: Native 该用哪个库 / 头文件？**  
A: 两条路径（§1.1）：**简易（推荐）** — `libmagic_sr_enable.a` + `mc_enable.h` → `MC_Enable*` / `MC_Disable`。**专业 / 进阶** — `libmagic_sr.a` + `mc_interface.h` → `MC_Init` / `MC_Process` / `MC_Uninit`。二选一，不要混用。

**Q: 链接报错找不到 `MC_Enable` / `MC_Disable`？**  
A: 链接的是仅核心的 `libmagic_sr.a`（会话路径）。若要用 Enable，请改用 `libmagic_sr_enable.a` 并引入 `mc_enable.h`（见 §1.1、§5.3 A）。
