# MagicCode Super-Resolution（MagicSR）用户使用说明书

版本：v2.0.0
适用：Native SDK
平台：Android（Vulkan / OpenGLES）、iOS / macOS（Metal）、Windows（Vulkan / Direct3D 11 / OpenGL 4.3）

English: [`User_Guide.md`](User_Guide.md)

---

## 1. 产品简介

MagicSR 是 MagicCode 超分辨率 SDK，可将输入的 GPU 纹理放大并增强细节，适用于游戏画面、相机预览、UI 纹理等场景。v2.0.0 提供空域超分与时域超分：空域适合单帧/无运动向量的简易接入；时域需要每帧深度、运动向量与抖动，走会话 API（见 §7）。

**空域推荐接入方式**（两步即可）：

1. `Enable`：输入一张 GPU 纹理，返回超分后的输出纹理
2. `Disable`：结束使用时释放内部会话与输出纹理

无需手动创建会话、选择后端或配置输入类型；这些由 `Enable` 内部自动完成。

Native 空域简易 API 为 `MC_Enable` / `MC_Disable`；完整时域使用 `MC_Init` / `MC_Process` / `MC_Uninit`。

### 1.1 Native 交付物：两条集成路径

Native SDK 提供**两套**静态库。请只选**一条**路径，不要混用：

| 路径 | 适用对象 | 链接 | 头文件 | 调用 |
|------|----------|------|--------|------|
| **简易路径（推荐）** | 多数应用 / 游戏 / 相机 | `libmagic_sr_enable.a`（核心 + Enable） | `mc_enable.h` | `MC_Enable*` / `MC_Disable` |
| **专业 / 进阶路径** | 需显式控制会话、后端或 CPU Buffer | `libmagic_sr.a`（仅核心） | `mc_interface.h` | `MC_Init` / `MC_Process` / `MC_Uninit` |

| 内容 | 简易路径 | 专业 / 进阶路径 |
|------|----------|-----------------|
| 头文件 | `interface/mc_enable.h` | `interface/mc_interface.h` |
| Android 库 | `lib/android/libmagic_sr_enable.a` | `lib/android/libmagic_sr.a` |
| iOS 库 | `lib/ios/libmagic_sr_enable.a` | `lib/ios/libmagic_sr.a` |
| macOS（Apple Silicon） | `lib/mac_arm/libmagic_sr_enable.a` | `lib/mac_arm/libmagic_sr.a` |
| Windows 库 | `lib/windows/libmagic_enable_sr.lib` | `lib/windows/libmagic_sr.lib` |

说明：

- 简易路径：**不必**再把 `mc_enable.c` 加入 App 编译；Enable 已包含在 `libmagic_sr_enable.a` 中。
- 仅核心的 `libmagic_sr.a` **不**导出 `MC_Enable*`——只链它会导致 Enable 相关符号未定义。
- **Native 应用**：按上表选一条路径（见 §5.1）；Apple 仍需链接 Metal / MetalKit 等系统框架。
- 发布包一般已自带 `libmagic_sr_enable.a`。若需从核心库**本地重打**合并库，见 §5.1 A 中的 `tools/build_enable_lib.sh`。

## 2. 快速开始

### 2.1 Native C

调用 `MC_Enable` 前，链接 `libmagic_sr_enable.a` 并 `#include "mc_enable.h"`。详见 §1.1、§5.1。

```c
#include "mc_enable.h"

void* out = MC_Enable(input_texture, 2.0f);  // RGBA GPU 纹理
if (out == NULL) { /* 失败 — 查看日志 [MagicSR][Enable] err=<code> */ }

/* 使用 out（借出指针，不要 free / CFRelease / glDelete） */

MC_Disable(NULL);  // 或 MC_Disable(out)；参数可忽略

/* 可选：指定模式 / 后端 */
/* void* out = MC_Enable_3params(input_texture, 2.0f, SPATIAL_SPEED_MODE); */
/* void* out = MC_Enable_4params(input_texture, 2.0f, SPATIAL_SPEED_MODE, MAGIC_BACKEND_DEFAULT); */
```

## 3. Enable 行为说明

| 项目 | 说明 |
|------|------|
| 功能 | 懒初始化会话 + 处理一帧 + 返回输出 GPU 纹理 |
| `scale` | `float`，空域范围 `[1.0, 8.0]`；`<= 0` 时默认为 `2.0`。Enable 不提供时域所需的 depth/motion/jitter |
| 会话复用 | 相同 `scale`、输入宽高、mode、backend 时复用内部会话与输出纹理 |
| 返回值 | 输出纹理指针；失败为 `NULL` / `IntPtr.Zero` / `0` |
| 所有权 | 输出由库持有，**只能**通过 `Disable` 释放 |

### 3.1 输入纹理格式（重要）

`Enable` 统一要求 **RGBA 系** GPU 纹理：

| 平台 / 后端 | 输入格式 | `Enable` 后端 |
|-------------|----------|----------------|
| iOS / macOS Metal | `RGBA8Unorm`（`MTLTexture*`） | Metal |
| Windows OpenGL（Enable 默认） | `RGBA8`（`GLuint` 转 `void*`） | OpenGL |
| Android OpenGLES | `RGBA8`（`GLuint` 转 `void*`） | OpenGLES |
| Android / Windows Vulkan | `RGB8Unorm` / `RGBA8` | Vulkan |

`MC_Enable_4params` 可显式选择 `MAGIC_BACKEND_VULKAN`；**不**接受 `MAGIC_BACKEND_D3D11`（Direct3D 11 时域请走 §7 会话 API）。

不要再向 `Enable` 传入 R8 单通道纹理。

### 3.2 尺寸 Hint（Android GLES / Vulkan — 必需）

在 **Android OpenGLES** 与 **Android Vulkan** 上，SDK 无法可靠查询输入纹理尺寸。调用 `Enable` 前**必须**先调用 `SetInputSizeHint` / `MC_Enable_SetInputSizeHint(width, height)`。未设置有效 hint（宽高需在 `[64, 4032]`）时，`Enable` 失败并返回 `MC_ENABLE_ERROR_SIZE_HINT_REQUIRED`（`-300006`）。

Native 路径必须在调用 `Enable` 前自行设置有效尺寸 hint。

Metal、Windows OpenGL 通常可查询尺寸，hint 可选。

### 3.3 尺寸与性能提示

- 输入宽高必须在 `[64, 4032]`。
- `scale` / 尺寸频繁变化会触发重建，影响性能。
- 失败时请查看日志中的 `[MagicSR][Enable] err=<code>`（见 `mc_enable.h` 中 `MC_ENABLE_ERROR_*`）。

## 4. 模型文件

多数场景不必手拷模型：先跑安装脚本，再按平台做极少几步即可。

### 4.0 一键放置模型（推荐）

`tools/setup_models.sh`（Windows：`tools\setup_models.bat`）**只负责拷贝文件**，不会自动调用 `SetModelDir` / `Enable`。
源目录固定为仓库内的 `model/`，默认拷贝 Enable 用的 **GPU** `.bin`（Metal / OpenGL / GLES / Vulkan 的 Speed + Balanced，共 8 个；缺文件会跳过）。

在仓库根目录执行。完整列表见 `./tools/setup_models.sh --help`。

#### 各子命令分别做什么

| 命令 | 把模型拷到哪里 | 典型用途 | 拷完后你还要做什么 |
|------|----------------|----------|-------------------|
| `demo`（或不带参数，默认即 `demo`） | Android：`demo/android/app/src/main/assets/model/`<br>iOS：`demo/ios/MagicCameraSR/MagicSRModels/` | 只跑仓库自带相机 demo | 按 demo 工程方式编译安装；demo 内会设模型路径 |
| `local` | `<repo>/MagicSRModels/` | Native / 本机调试 | **必须**再调用 `MC_Enable_SetModelDir("<repo>/MagicSRModels 的绝对路径")`（或 `SetModelPath` 指向某个 `.bin`）。仅把文件放进该文件夹**不会**让任意 App 自动找到 |
| `dir --dest <目录>` | 你指定的任意目录 | 自定义布局 | `MC_Enable_SetModelDir("<该目录绝对路径>")` |
| `adb` | 手机 `/storage/emulated/0/Documents/MagicSRModels/` | Android 真机快速验证 | `MC_Enable_SetModelDir("/storage/emulated/0/Documents/MagicSRModels")` |
| `all` | `demo` + `local` | 一次准备多个 Native 目标 | 各目标仍按上表在代码里设路径 |

```bash
# macOS / Linux 示例
./tools/setup_models.sh demo
./tools/setup_models.sh local
./tools/setup_models.sh adb
```

```bat
REM Windows
tools\setup_models.bat demo
tools\setup_models.bat local
```

**常见误解：**

- `local` ≠ 全局自动搜索。它只创建 `<repo>/MagicSRModels/`。若进程当前工作目录（cwd）恰好是仓库根，默认搜索里的相对路径 `MagicSRModels/<文件名>` **有可能**碰巧命中；正式 App 的 cwd 通常不是仓库根，**请显式 `SetModelDir` / `SetModelPath`**。
- `demo` 与 `build_demo.sh`：后者在编 Android 时也会把 GLES 模型拷进 assets；`setup_models.sh demo` 则同时准备 Android + iOS demo 目录，用途是「先摆好模型」。

### 4.1 用代码设置模型路径（推荐 API）

`SetModelPath` / `SetModelDir` **不是** C API 语法上的强制参数，但生产集成中应视为** practically 必做**：不调用时依赖 §4.4 的隐式搜索，在手机/游戏引擎上很容易找不到模型（`-300009`）。

在 `Enable` **之前**调用：

Native API：`MC_Enable_SetModelPath("/abs/path/model.bin")` 或 `MC_Enable_SetModelDir("/abs/path/MagicSRModels")`。

`SetModelPath` 优先于 `SetModelDir`。传空/NULL 可清除。不要用环境变量设置模型路径。

`SetModelDir` 会在该目录下**递归**查找 §4.3 中的默认文件名（最多 4 层），不会按任意 `.bin` 名乱扫。


### 4.2 脚本之后（Native）

| 目标平台 | 当前可用的具体运行时路径 |
|----------|--------------------------|
| Android | `/storage/emulated/0/Documents/MagicSRModels/<model>.bin`（也支持 `/sdcard/Documents/MagicSRModels/`） |
| iOS | 应用沙箱 / Bundle 下的 `<model>.bin`，再 `MC_Enable_SetModelPath(fullPath)`（与 demo 一致） |

移动端**不要**只依赖相对路径 `MagicSRModels/`——它相对的是进程工作目录，打包后常常不是你以为的位置。

**Native（推荐）**

1. `./tools/setup_models.sh local` 或 `dir --dest <path>`（Android 真机可用 `adb`）
2. 在 `MC_Enable` 之前用代码设置路径：

```c
/* 推荐：指向某一个 .bin 的完整路径 */
MC_Enable_SetModelPath("/absolute/path/to/magic_gles_speed_gpu_params.bin");

/* 或：指向含默认文件名的目录 */
MC_Enable_SetModelDir("/absolute/path/to/MagicSRModels");
```

| 平台 | 实用绝对路径 |
|------|----------------|
| Android | 应用 `filesDir` / 从 assets 解压出的路径；或 `/storage/emulated/0/Documents/MagicSRModels/` |
| iOS | Bundle 资源路径，或沙箱 `Documents/...`（见 `demo/ios`） |
| Windows | 如 `C:\\YourApp\\MagicSRModels\\magic_gl_speed_gpu_params.bin` |
| macOS | App 资源目录 / 安装目录下的绝对路径 |

相对搜索（`./MagicSRModels/`、`./<name>.bin`）只有在进程 cwd 恰好是该目录时才有效——适合本地工具，不适合正式发版应用。

### 4.3 平台 × 后端 × 默认模型名

| 平台 | 后端 | Speed（`SPATIAL_SPEED_MODE`） | Balanced（`SPATIAL_BALANCED_MODE`） |
|------|------|--------------------------------|------------------------|
| iOS / macOS | Metal | `magic_metal_speed_gpu_params.bin` | `magic_metal_balanced_gpu_params.bin` |
| Windows | OpenGL | `magic_gl_speed_gpu_params.bin` | `magic_gl_balanced_gpu_params.bin` |
| Android | OpenGLES | `magic_gles_speed_gpu_params.bin` | `magic_gles_balanced_gpu_params.bin` |
| Android | Vulkan | `magic_vulkan_speed_gpu_params.bin` | `magic_vulkan_balanced_gpu_params.bin` |

仍兼容旧别名：`magic_veryfast_gpu_params.bin`、`magic_veryfast_gles_params.bin`、`magic_speed_gpu_params.bin`。

### 4.4 `Enable` 如何查找模型（参考）

内部搜索顺序：

1. **显式文件**：`MC_Enable_SetModelPath`（若已设置且可读）
2. 对 §4.3 中的每个默认文件名 `<name>`，依次尝试：
   - **显式目录**：`SetModelDir` 指向的目录树下递归查找该 basename（深度 ≤ 4）
   - **相对目录**：`MagicSRModels/<name>` —— 相对**进程当前工作目录（cwd）**，不是「自动找到磁盘上任意名为 MagicSRModels 的文件夹」，也不是自动等于 `<repo>/MagicSRModels`
   - **相对文件**：`./<name>`（同样相对 cwd）
   - **Android 固定绝对路径**（未设 SetModel* 时的回退）：
     `/sdcard/Documents/MagicSRModels/<name>`、
     `/storage/emulated/0/Documents/MagicSRModels/<name>`、
     `/storage/emulated/0/Documents/<name>`
3. **iOS / macOS**：App Bundle 内按默认文件名查找

因此：

| 做法 | 是否可靠 |
|------|----------|
| `SetModelPath` / `SetModelDir`（绝对路径） | 推荐，发版应用应使用 |
| `setup_models.sh adb` + 默认 Android Documents 回退 | 真机调试可用；仍建议显式 `SetModelDir` |
| 仅 `setup_models.sh local`，不调 SetModel* | 仅当 cwd = 仓库根时可能碰巧成功；**不要**依赖 |
| 相对路径 `MagicSRModels/` | 随 cwd 变化，正式包不可靠 |

找不到模型时，`Enable` 失败并返回 `MC_ENABLE_ERROR_MODEL_NOT_FOUND`（`-300009`）。

## 5. 集成步骤

### 5.1 Native

按 §1.1 只选**一条**路径。

#### A. 简易路径（推荐）— Enable API

链接 `libmagic_sr_enable.a` + 引入 `mc_enable.h`。无需自行编译 `mc_enable.c`。

1. 头文件：`interface/mc_enable.h`
2. 链接合并库：
   - Android：`lib/android/libmagic_sr_enable.a`
   - iOS：`lib/ios/libmagic_sr_enable.a`
   - Windows：`lib/windows/libmagic_enable_sr.lib`（含 Vulkan/D3D11/OpenGL 时域超分；只需这一个库，不要再链 `magic_sr_win_vk` / `magic_vulkan_temporal` / `magic_vulkan_taau`；不要再使用旧文件名 `libmagic_sr_enable.lib`）
3. iOS 还需链接 Metal / MetalKit 等相关系统框架；Windows 还需系统/SDK 依赖（`d3d11` `opengl32` `vulkan-1` 等）
4. 调用 `MC_Enable_SetModelPath` / `MC_Enable_SetModelDir`（推荐）→ `MC_Enable` / `MC_Disable`

**本地重打合并库（可选）**

仓库通常已提供上述 `libmagic_sr_enable.a`。若你更新了 `interface/mc_enable*.c/m`，或只有核心 `libmagic_sr.a`、需要重新生成 Enable 合并库，在仓库根目录执行：

```bash
./tools/build_enable_lib.sh          # 默认同时打 Android + iOS
./tools/build_enable_lib.sh android  # 仅 Android
./tools/build_enable_lib.sh ios      # 仅 iOS
```

脚本会：

1. 找到已有核心库 `libmagic_sr.a`（优先 `lib/<platform>/`，其次私有工程 `build/` 输出）
2. 编译 `mc_enable.c`（iOS 另含 `mc_enable_metal.m`）
3. 与核心库合并，写出：
   - `lib/android/libmagic_sr_enable.a`
   - `lib/ios/libmagic_sr_enable.a`

前置条件：本机有对应工具链（Android NDK；iOS 需 Xcode / iphoneos SDK）。这与 `setup_models.sh`（只拷模型）无关——`build_enable_lib.sh` 只管**编库**。

Android NDK / CMake 示例：

```cmake
add_library(my_app SHARED native-lib.cpp)
add_library(magic_sr_enable STATIC IMPORTED)
set_target_properties(magic_sr_enable PROPERTIES
  IMPORTED_LOCATION ${MAGIC_SR_ROOT}/lib/android/libmagic_sr_enable.a)
target_link_libraries(my_app magic_sr_enable ...)
```

iOS Xcode 示例：链接 `-lmagic_sr_enable`（搜索路径指向 `lib/ios/`），**不要**把 `mc_enable.c` / `mc_enable_metal.m` 加入 Compile Sources。

#### B. 专业 / 进阶路径 — 会话 API

链接仅核心库 `libmagic_sr.a` + 引入 `mc_interface.h`。不使用 Enable，走会话 API：

1. 头文件：`interface/mc_interface.h`
2. 链接：`lib/android/libmagic_sr.a`、`lib/ios/libmagic_sr.a`、`lib/mac_arm/libmagic_sr.a` 或 `lib/windows/libmagic_sr.lib`
3. 调用 `MC_Init` → `MC_Process` → `MC_Uninit`（时域见 §7）

## 6. 内存与生命周期（必读）

1. **`Enable` 返回的输出纹理是借出（borrowed）指针**
   - 不要 `free` / `delete` / `CFRelease` / `glDeleteTextures` / `DestroyImmediate`
   - iOS Metal：错误 `CFRelease` 会在释放点直接 `abort`
2. **唯一合法释放方式是 `Disable()`**
3. `Disable` 之后，此前返回的输出指针全部失效，不可再使用
4. 可反复 `Enable`；在 `scale` 与尺寸不变时会复用内部资源
5. `Disable` 后再次 `Enable` 会重新创建会话

## 7. 时域超分

时域超分用相邻帧的颜色、深度和运动向量做历史累积，适合已有 jittered 相机与 motion vector 的游戏/引擎管线。它**不是** Enable 的扩展参数，正式接入必须走会话 API。

| 项 | 合同 |
|----|------|
| 头文件 / 库 | `interface/mc_interface.h` + `libmagic_sr.a`（Windows：`lib/windows/libmagic_sr.lib`） |
| API | `MC_Init` → 每帧 `MC_Process` → `MC_Uninit` |
| 空域 scale | `[1.0, 8.0]`（以实际后端/模型为准） |
| 时域 scale | `(1.0, 8.0]`（**不含 1.0**） |
| CPU | **不可用**（`MAGIC_BACKEND_X86` / `NEON` 返回 `MC_ERROR_INIT_BACKEND_UNAVAILABLE`） |
| 已验证 vs API | API 支持 `(1, 8]`；精确 2× 有优化核。文档不声称所有倍率/设备均已实机验证 |

### 7.1 模式与选择

`alg_mode_e`（`mc_interface.h`）：

| 值 | 枚举 | 用途 |
|----|------|------|
| 0 | `SPATIAL_SPEED_MODE` | 空域，优先吞吐 |
| 1 | `SPATIAL_BALANCED_MODE` | 空域，质量与开销折中 |
| 2 | `TEMPORAL_SPEED_MODE` | 时域，优先吞吐 |
| 3 | `TEMPORAL_BALANCED_MODE` | 时域，走 canonical FSR 族流程 |

如何选时域模式：

- **TEMPORAL_SPEED_MODE**：延迟更敏感。Apple Metal、Android/Windows Vulkan、Android OpenGLES 当前走轻量 Convert→Activate→Upscale 管线；Windows Direct3D 11 与桌面 OpenGL 4.3 走与 Balanced 相同的 FSR 族时域路径（不是另一套客户 API）。
- **TEMPORAL_BALANCED_MODE**：所有 GPU 时域后端归入 canonical FSR 族流程。桌面 Balanced 的 edge-resolve 实际支持 Windows Vulkan、Windows Direct3D 11、桌面 OpenGL 4.3 与 Apple Metal；Android Vulkan / OpenGLES 不做 edge-resolve。若开启输出锐化（`enable_sharpening`），RCAS 在 edge-resolve **之后**。
- 时域模式关闭空域预处理。不要把内部实现名当作必须配置的公开 API。

### 7.2 最低输入

`MC_Init`（`input_param_t`）至少设置：

- `struct_size = sizeof(input_param_t)`（`0` 也表示当前 sizeof）
- `alg_mode`：`TEMPORAL_SPEED_MODE` 或 `TEMPORAL_BALANCED_MODE`
- `backend`、`input_type`（GPU 纹理）、`width` / `height`（`[64, 4032]`）、`scaler_factor` ∈ `(1, 8]`
- `gpu_context`（见 §7.4）。创建期可选：`depth_reversed`、`depth_infinite`、`hdr_color`（全 0 = 常规 Z、有限远平面、LDR）。三者在句柄生命周期内不可变；`MC_Control` 改尺寸不会重置它们。

每帧 `MC_Process(handle, &frame)` 需要：

| 位置 | 字段 | 要求 |
|------|------|------|
| `magic_frame_t` | `image_in` / `image_out` | 颜色与输出 GPU 资源（调用方持有） |
| `magic_frame_t` | `frame` | 非 NULL，指向 `temporal_frame_t` |
| `magic_frame_t` | `command_buffer` | Vulkan **必须**是正在录制的 `VkCommandBuffer`；Metal 可为空（库内提交）或传入调用方 `MTLCommandBuffer`；D3D11 / GL / GLES 为空（库内提交） |
| `temporal_frame_t` | `struct_size` | `sizeof(temporal_frame_t)` |
| `temporal_frame_t` | `depth` / `motion` | 与输入同分辨率的 GPU 资源 |
| `temporal_frame_t` | `jitter_offset_x/y` | 输入像素、左上原点、+X 右、+Y 下 |
| `temporal_frame_t` | `frame_index` / `reset_history` | 连续帧应为 last+1；切场景/传送时非 0 |
| `temporal_frame_t` | `camera_near` / `camera_far` / `camera_fov_y` | 视空间距离与垂直 FOV（弧度） |

可选：`reactive`、`transparency`、`enable_sharpening` + `sharpness`、`exposure_texture`（1×1 R32F）、`pre_exposure`（`0` 表示 1.0）、`motion_vector_scale_*`、`mv_jitter`、`view_to_meters`、`frame_time_delta_ms`。

### 7.3 C 示例（Vulkan）

字段名以 `mc_interface.h` 为准；按后端写入 `magic_data_e` 的**一个**成员。

句柄跨帧持有。`temporal_vk_process` 只把计算录进调用方已在录制的 `VkCommandBuffer`。库不 begin、end、submit 或 wait。调用方提交该缓冲并等待 GPU 完成后，再在 shutdown 调用 `temporal_vk_shutdown`（`MC_Uninit`）。`layout=0` 即 UNDEFINED，校验失败，也包括 `image_out.layout`。

```c
#include "mc_interface.h"
#include <string.h>
/* Plus the Vulkan headers that define VkPhysicalDevice / VkDevice / VkCommandBuffer. */

static void *g_temporal_vk;

int temporal_vk_init(VkPhysicalDevice phys, VkDevice dev,
                     unsigned in_w, unsigned in_h)
{
    input_param_t p;

    memset(&p, 0, sizeof(p));
    p.struct_size = (uint32_t)sizeof(p);
    p.input_type = INPUT_TEXTURE_RGB8Unorm;
    p.width = in_w;
    p.height = in_h;
    p.scaler_factor = 2.0f;              /* (1, 8] */
    p.alg_mode = TEMPORAL_SPEED_MODE;    /* or TEMPORAL_BALANCED_MODE */
    p.backend = MAGIC_BACKEND_VULKAN;
    p.log_level = MAGIC_LOG_ERROR;
    p.gpu_context.physical_device = phys;
    p.gpu_context.device = dev;
    /* optional create-stage: p.depth_reversed / p.depth_infinite / p.hdr_color */

    g_temporal_vk = MC_Init(&p);
    return g_temporal_vk ? 0 : -1;
}

int temporal_vk_process(VkCommandBuffer cmd,
                        uint64_t color, uint64_t depth, uint64_t motion,
                        uint64_t output,
                        uint32_t color_fmt, uint32_t depth_fmt,
                        uint32_t mv_fmt, uint32_t out_fmt,
                        uint32_t color_layout, uint32_t depth_layout,
                        uint32_t mv_layout, uint32_t output_layout,
                        unsigned frame_index, int reset)
{
    temporal_frame_t tf;
    magic_frame_t frame;

    if (!g_temporal_vk)
        return -1;

    memset(&tf, 0, sizeof(tf));
    tf.struct_size = (uint32_t)sizeof(tf);
    tf.depth.handle.vk_image = depth;
    tf.depth.format = depth_fmt;
    tf.depth.layout = depth_layout;
    tf.motion.handle.vk_image = motion;
    tf.motion.format = mv_fmt;
    tf.motion.layout = mv_layout;
    tf.jitter_offset_x = 0.0f;           /* input pixels, +X right */
    tf.jitter_offset_y = 0.0f;           /* +Y down */
    tf.motion_vector_scale_x = 0.0f;     /* (0,0) → (in_w, in_h) for UV MVs */
    tf.motion_vector_scale_y = 0.0f;
    tf.frame_index = frame_index;
    tf.reset_history = reset;
    tf.camera_near = 5.0f;
    tf.camera_far = 65536.0f;
    tf.camera_fov_y = 1.0f;              /* radians */
    tf.view_to_meters = 1.0f;
    tf.frame_time_delta_ms = 16.67f;

    memset(&frame, 0, sizeof(frame));
    frame.image_in.handle.vk_image = color;
    frame.image_in.format = color_fmt;
    frame.image_in.layout = color_layout;
    frame.image_out.handle.vk_image = output;
    frame.image_out.format = out_fmt;
    frame.image_out.layout = output_layout;
    frame.frame = &tf;
    frame.command_buffer = cmd;          /* must already be recording */

    /* Records into cmd only. Caller submits and waits; this function does not. */
    return MC_Process(g_temporal_vk, &frame);
}

int temporal_vk_shutdown(void)
{
    int rc;

    /* Caller must have submitted and waited on recorded GPU work first. */
    rc = MC_Uninit(g_temporal_vk);
    g_temporal_vk = NULL;
    return rc;
}
```

其他后端把 union 换成对应成员：Metal / D3D11 用 `handle.pointer`；GL / GLES 用 `handle.gl_texture`。D3D11 在 `MC_Init` 时 `gpu_context.device` 必填（`device_context` 为 NULL 表示 immediate）。GL/GLES 不切换上下文，首次 `MC_Process` 时调用线程必须已有当前上下文。

### 7.4 后端资源合同

| 后端 | 平台 | `gpu_context` | 每帧 `command_buffer` | 资源 union |
|------|------|---------------|------------------------|------------|
| Metal | iOS / macOS | `device` 可 NULL（系统默认） | 可选 | `pointer` = `MTLTexture*` |
| Vulkan | Android / Windows | `physical_device` + `device` **必填**；`get_device_proc_addr` 可 NULL | **必须正在录制** | `vk_image` = `VkImage` |
| Direct3D 11 | Windows | `device` **必填**；`device_context` 可 NULL | 不使用（NULL） | `pointer` = `ID3D11Texture2D*` |
| OpenGL 4.3 | Windows | 当前上下文；库不 make current | 不使用（NULL） | `gl_texture` = `GLuint` |
| OpenGLES | Android | 当前上下文；库不 make current | 不使用（NULL） | `gl_texture` = `GLuint` |
| x86 / NEON | — | 时域不可用 | — | — |

所有权与同步：

- 调用方拥有全部应用侧 GPU 对象；库不 retain / free 它们，只拥有内部 history / scratch / pipeline。
- `magic_resource_t` **没有**宽高。颜色/深度/MV/mask 必须与句柄输入尺寸一致，`image_out` 与输出尺寸一致——这是调用方合同，库不查询 `VkImage` 尺寸。
- `format` 为后端原生枚举；`0` 表示未提供，库在逐帧路径上不猜测。
- Vulkan：`layout` 必须是进入 `MC_Process` 时的真实 layout（`0` = UNDEFINED，校验失败）。库会把输入转到 `GENERAL` 做计算，再恢复输入 layout；输出保持 `GENERAL`。库不 begin/end/submit/wait 命令缓冲。销毁 `MC` 句柄或改尺寸前，须完成此前录制的 GPU 工作。
- 同一 `VkDevice` 上的 `physical_device` / `device` / 图像必须匹配。

### 7.5 reset、jitter、MV、depth

- **Motion**：current → previous。当前像素加上解码后的 MV 落在上一帧；库**不会**取反 MV。
- **坐标**：jitter 与输出均为左上原点，+X 右，+Y 下。jitter 单位为**输入像素**。
- **`motion_vector_scale_x/y`**：唯一的 MV 数值换算。`stored_mv * scale` = 上述合同下的输入像素位移。`(0,0)` 默认 `(input_width, input_height)`（UV 存储）。单轴为 0 被拒绝。像素 MV 用 `(1,1)`；+Y-up 存储可用负 Y。
- **`mv_jitter`**：`0` / `MC_MV_JITTER_EXCLUDED` 表示相机 jitter 只放在 `jitter_offset_*`（推荐）；`MC_MV_JITTER_INCLUDED` 表示存储的 MV 已含本帧 jitter。
- **Depth**：始终是 GPU device depth，范围 `[0, 1]`。不接受线性视空间深度，库不转换。reversed-Z / infinite far / HDR 只在 **`MC_Init` 创建期**设置。
- **`reset_history`**：非 0 丢弃时域历史（读档、传送、相机硬切）。不要每帧都置位。
- **`frame_index`**：非 last+1 时记录警告 `MC_WARNING_TEMPORAL_FRAME_INDEX`，历史可能过期，但不是硬失败。

### 7.6 Mask 默认行为

- `reactive` / `transparency` 均为可选。显式传入的纹理**每通道优先**。
- 调用方未提供时，库会**内部派生近似 mask**。这**不等于**拥有语义透明度 mask。
- Speed（Metal / Vulkan / GLES 轻量路径）：缺省时可派生 reactive 与近似 transparency（依赖 color.a / coverage 等证据；无 alpha 时自动 transparency 保持 0）。
- FSR 族路径（所有后端的 Balanced；以及 D3D11 / 桌面 GL 的 Speed）：缺 reactive 时派生近似 reactive；缺 transparency 时绑定内部**零纹理**，**不会**从 color.a 生成语义透明度。
- 两种时域模式默认启用深度+MV **历史拒绝**。
- 高级诊断（非正式客户配置）：环境变量 `MAGICSR_TAAU_AUTO_MASK=0`、`MAGICSR_TAAU_HIST_REJECT=0` 可关闭上述默认行为。生产集成应通过 `alg_mode` 与显式 mask 选择，而不是依赖环境变量。

### 7.7 错误与排障

| 现象 | 常见原因 |
|------|----------|
| `MC_Init` 返回 NULL / `MC_ERROR_INIT_SCALER_OUT_OF_RANGE` | 时域 scale 为 1.0 或不在 `(1, 8]` |
| `MC_ERROR_INIT_BACKEND_UNAVAILABLE` | CPU 后端，或本构建未包含该 GPU 时域 |
| `MC_ERROR_INIT_GPU_CREATE_FAILED` | Vulkan 缺 physical/device；D3D11 缺 device |
| `MC_ERROR_TEMPORAL_NULL_FRAME` | `magic_frame_t.frame == NULL` |
| `MC_ERROR_TEMPORAL_MISSING_COLOR/OUTPUT/DEPTH/MOTION` | 对应 native handle 为空 |
| `MC_ERROR_TEMPORAL_COMMAND_BUFFER` | Vulkan 未传入正在录制的 command buffer |
| `MC_ERROR_TEMPORAL_FORMAT` | Vulkan layout 为 UNDEFINED，或 format 不被该槽位接受 |
| `MC_ERROR_TEMPORAL_MV_SCALE` | scale 单轴为 0 或非有限 |
| `MC_ERROR_TEMPORAL_CAMERA_NEAR_FAR` | 有限远平面要求 `0 < near < far`；无限远要求 `near > 0` |
| 残影 / 拖影 | 未在硬切时 `reset_history`；MV 方向或 scale 错误；jitter 未按 +Y down |
| 边缘闪烁 | 缺显式 mask 时仅有近似派生；可提供 reactive/transparency |
| Enable 时域失败 | Enable 没有 depth/motion/jitter，见 §7.8 |

用 `MC_Control(..., QUERY_STATUS, ...)` 读取 `output_status_params_t`。`temporal_status_valid` 仅在最近一次成功的时域 `MC_Process` 后为非 0。

### 7.8 与 Enable 的边界

| | Enable（`MC_Enable*`） | 会话 API（`MC_Init` / `MC_Process`） |
|--|------------------------|--------------------------------------|
| 库 | `libmagic_sr_enable.a` / `libmagic_enable_sr.lib` | `libmagic_sr.a` / `libmagic_sr.lib` |
| 每帧输入 | **一张**颜色纹理 | 颜色 + 输出 + depth + motion + jitter + camera |
| 时域枚举 | 范围检查可能接受 | 正式时域入口 |
| 完整时域 | **否** | **是** |

不要把 `MC_Enable_3params(..., TEMPORAL_SPEED_MODE)` 宣传为完整时域。完整时域请在 Native 会话 API 上集成。

## 9. 常见问题

**Q: Enable 返回空指针？**
A: 查看日志 `[MagicSR][Enable] err=<code>`。常见原因：找不到模型（`-300009`）、Android 未设 size hint（`-300006`）、尺寸非法（`-300008`）、或 `MC_Init` / `MC_Process` 失败。同时确认 RGBA 输入与 `SetModelDir` / 模型路径。

**Q: 为什么 iOS 不能再用 R8？**
A: 当前 `MC_Enable` 默认输入为 RGBA。R8 仅适用于旧的会话式 Metal/GLES 高级路径，不适用于 `Enable`。

**Q: 输出花屏 / 全黑？**
A: 确认输入为 RGBA8、未对输出做非法释放，以及（Android GLES/Vulkan）`SetInputSizeHint` 与真实纹理尺寸一致；查看日志错误码。



**Q: 可以多实例同时 Enable 吗？**
A: `Enable` 路径是进程内单例。多路并发请改用会话式 API，或串行共享同一 `Enable` 会话。

**Q: Native 该用哪个库 / 头文件？**
A: 两条路径（§1.1）：**简易（推荐空域）** — `libmagic_sr_enable.a` + `mc_enable.h` → `MC_Enable*` / `MC_Disable`。**专业 / 进阶（含完整时域）** — `libmagic_sr.a` + `mc_interface.h` → `MC_Init` / `MC_Process` / `MC_Uninit`。二选一，不要混用。

**Q: 链接报错找不到 `MC_Enable` / `MC_Disable`？**
A: 链接的是仅核心的 `libmagic_sr.a`（会话路径）。若要用 Enable，请改用 `libmagic_sr_enable.a` 并引入 `mc_enable.h`（见 §1.1、§5.1 A）。

**Q: `libmagic_sr_enable.a` 怎么生成？和 `setup_models.sh` 有什么区别？**
A: 发布包一般已自带该库。本地重打用 `./tools/build_enable_lib.sh`（把核心 `libmagic_sr.a` 与 `mc_enable` 合并，见 §5.1 A）。`setup_models.sh` 只拷贝模型 `.bin`，不编库。

**Q: 时域能走 Enable 吗？**
A: 不能作为完整入口。Enable 只有单张颜色纹理，没有 per-frame depth / motion / jitter。完整时域见 §7。

**Q: 时域支持哪些后端？**
A: Android Vulkan / OpenGLES、Apple Metal、Windows Vulkan / Direct3D 11 / OpenGL 4.3。CPU 时域不可用。API 支持 scale `(1, 8]`，不声称所有倍率均已实机验证。

**Q: 不传 mask 是否等于有透明度 mask？**
A: 否。缺少时库会内部派生**近似** mask，显式纹理每通道优先。FSR 族路径不会从 color.a 生成语义 transparency。
