# MagicCode Super-Resolution（MagicSR）用户使用说明书

版本：v2.1.0
适用：Native SDK（C API）
平台：Android（Vulkan / OpenGLES）、iOS / macOS（Metal）、Windows（Vulkan / Direct3D 11 / OpenGL 4.3）、macOS（Apple Silicon / x86_64）

English: [`User_Guide.md`](User_Guide.md)

---

## 1. 产品简介

MagicSR 是 MagicCode 超分辨率 SDK，可将输入的图像或 GPU 纹理放大并显著增强画面细节，适用于相机预览与处理、移动与桌面游戏渲染、UI 纹理缩放等场景。

从 **v2.1.0** 开始，MagicSR 在各个平台均统一为单一核心静态库，并精简为 3 个公开 C ABI 函数：

```c
int MC_Enable(void **handle, magic_frame_t *frame, input_param_t *param, output_status_params_t *status_info);
int MC_Disable(void *handle);
char *MC_GetVersion(void);
```

### v2.1.0 核心优势

- **单一平台交付物**：每个平台仅提供一个静态库（`libmagic_sr.a` / `libmagic_sr.lib`）和一个公共头文件（`interface/mc_interface.h`），无需再链接旧版 enable 包装库或引用额外头文件。
- **统一公开接口**：句柄初始化、每帧超分计算、动态参数重配与状态查询全部收敛至 `MC_Enable`；资源释放由 `MC_Disable` 完成。
- **空域与时域全覆盖**：单帧空域超分辨率与多帧时域超分辨率均使用同一套 `MC_Enable` 签名，调用形式整洁统一。

## 2. 交付清单与系统要求

### 2.1 静态库与头文件

| 目标平台 | 静态库文件 | 公共头文件 |
|----------|------------|------------|

| iOS | `lib/ios/libmagic_sr.a` | `interface/mc_interface.h` |
| macOS（Apple Silicon） | `lib/mac_arm/libmagic_sr.a` | `interface/mc_interface.h` |
| macOS（x86_64） | `lib/mac_x86/libmagic_sr.a` | `interface/mc_interface.h` |
| Windows | `lib/windows/libmagic_sr.lib` | `interface/mc_interface.h` |

### 2.2 系统与硬件环境要求

- **Android**：Android 8.0（API Level 26）及以上，支持 Vulkan 与 OpenGLES 3.1+。
- **iOS / iPadOS**：iOS 13.0+ / iPadOS 13.0+ 及以上，支持 Apple Metal。
- **macOS**：macOS 12.0 及以上（Apple Silicon arm64 或 Intel x86_64）。
- **Windows**：Windows 10 64 位及以上，支持 Vulkan、Direct3D 11、OpenGL 4.3。
- **分辨率范围**：输入图像宽高支持 `[64, 4032]` 像素。
- **放大倍率**：
  - 空域超分：`[1.0, 8.0]`
  - 时域超分：`(1.0, 8.0]`（不支持 1.0 倍率）

## 3. 核心 API 规范

所有功能通过 `interface/mc_interface.h` 中的 3 个函数提供：

### 3.1 `MC_Enable`

```c
int MC_Enable(void **handle, magic_frame_t *frame, input_param_t *param, output_status_params_t *status_info);
```

- **`handle`（void \*\*handle，必填）**：指向调用方算法句柄指针的地址。
  - **隐式初始化**：若 `*handle == NULL`，`MC_Enable` 将其视为首次调用，并使用传入的 `param` 创建并初始化内部句柄（此时 `param` 必须非空）。
  - **完整性校验**：若 `*handle != NULL`，会自动验证句柄的内存完整性标识（`0x11223344`，`0xaabbccdd`）。
- **`frame`（magic_frame_t \*，可选）**：当前帧的输入输出资源。
  - 当 `frame != NULL` 时：执行当前帧的超分辨率处理。
  - 当 `frame == NULL` 时：跳过图像处理（常用于单独初始化句柄或单独查询状态）。
- **`param`（input_param_t \*，后续调用可选）**：算法配置参数。
  - 首次调用（`*handle == NULL`）时必须传入。
  - 在后续调用（`*handle != NULL`）中，若传入非空 `param`，库会检查可变参数（`width`、`height`、`scaler_factor`、`alg_mode`、`log_level`、`spatial_sharpen_level`、`input_type`）是否变更；若变更则触发平滑重初始化；若参数无变动或传入 `NULL`，则维持现有配置继续运行。
- **`status_info`（output_status_params_t \*，可选）**：用于接收执行耗时与状态统计信息的结构体指针，不需要时传 `NULL`。
- **返回值**：成功返回 `0`；失败返回负数错误码（`MC_ERROR_*`）。

### 3.2 `MC_Disable`

```c
int MC_Disable(void *handle);
```

- 释放 `handle` 关联的所有内部资源与内存。
- 传入 `NULL` 安全无操作。
- 调用后句柄失效，不可再次用于其他 API。

### 3.3 `MC_GetVersion`

```c
char *MC_GetVersion(void);
```

- 返回算法库的版本字符串（如 `"v2.1.0"`）。返回的指针指向静态常量，切勿手动 `free`。

## 4. 快速接入：空域超分辨率

空域超分针对单帧图像进行放大与画质增强，无需运动向量或深度缓冲。

### 4.1 基本生命周期示例

```c
#include "mc_interface.h"
#include <string.h>

void *g_handle = NULL;

int init_and_process(magic_resource_t in_tex, magic_resource_t out_tex, unsigned int in_w, unsigned int in_h)
{
    input_param_t param;
    memset(&param, 0, sizeof(param));
    param.struct_size = (uint32_t)sizeof(param);
    param.input_type = INPUT_TEXTURE_RGB8Unorm;
    param.width = in_w;
    param.height = in_h;
    param.scaler_factor = 2.0f;
    param.alg_mode = SPATIAL_SPEED_MODE;      /* 或 SPATIAL_BALANCED_MODE */
    param.backend = MAGIC_BACKEND_METAL;      /* 或 VULKAN, OPENGLES, D3D11 等 */
    param.log_level = MAGIC_LOG_ERROR;
    strncpy(param.model_path, "/path/to/model.bin", sizeof(param.model_path) - 1);

    magic_frame_t frame;
    memset(&frame, 0, sizeof(frame));
    frame.image_in = in_tex;
    frame.image_out = out_tex;
    frame.frame = NULL;                       /* 空域模式传 NULL */

    output_status_params_t status;
    int ret = MC_Enable(&g_handle, &frame, &param, &status);
    if (ret != 0) {
        /* 处理错误：查看 status.error_code 或返回值 */
        return ret;
    }

    /* 后续相同配置的帧直接复用句柄： */
    /* ret = MC_Enable(&g_handle, &frame, NULL, &status); */

    return 0;
}

void shutdown(void)
{
    if (g_handle) {
        MC_Disable(g_handle);
        g_handle = NULL;
    }
}
```

### 4.2 算法模式选择

| 模式数值 | 枚举常量 | 性能与质量特征 | 典型适用场景 |
|----------|----------|----------------|--------------|
| `0` | `SPATIAL_SPEED_MODE` | 高吞吐率、极低 GPU/CPU 耗时 | 移动端相机实时预览、高帧率节能模式 |
| `1` | `SPATIAL_BALANCED_MODE` | 细节恢复更强、质感更好 | 画质优先的空域渲染、静态图超分 |
| `2` | `TEMPORAL_SPEED_MODE` | 吞吐优先的时域超分 | 移动端与 VR 高帧率游戏 |
| `3` | `TEMPORAL_BALANCED_MODE` | 标杆级 FSR 架构时域超分 | 桌面端及高画质主机/PC 游戏渲染 |

## 5. 时域超分辨率

时域超分利用当前帧与历史帧的时间一致性，结合颜色、深度缓冲、运动向量与相机亚像素抖动重建高分辨率图像。

### 5.1 时域输入要求

将 `param.alg_mode` 设置为 `TEMPORAL_SPEED_MODE` 或 `TEMPORAL_BALANCED_MODE`，并将填好的 `temporal_frame_t` 结构体赋值给 `frame.frame`：

| 字段 / 资源 | 说明 | 要求 |
|-------------|------|------|
| `magic_frame_t.image_in` | 当前帧低分辨率颜色纹理 | 输入分辨率，RGB8Unorm / RGBA8 |
| `magic_frame_t.image_out` | 超分输出颜色纹理 | 放大后的目标输出分辨率 |
| `magic_frame_t.frame` | 指向 `temporal_frame_t` 的指针 | **时域模式下必须非空** |
| `magic_frame_t.command_buffer` | GPU 命令缓冲 | Vulkan：正在录制的 `VkCommandBuffer`；Metal：可选；其余为 NULL |
| `temporal_frame_t.struct_size` | 结构体大小（保证 ABI 兼容） | `sizeof(temporal_frame_t)` |
| `temporal_frame_t.depth` | 设备深度缓冲（范围 `[0, 1]`） | 输入分辨率 |
| `temporal_frame_t.motion` | 运动向量（MV） | 输入分辨率，方向为当前帧 → 历史帧 |
| `temporal_frame_t.jitter_offset_x/y` | 相机亚像素抖动（输入像素单位） | 左上角原点，+X 向右，+Y 向下 |
| `temporal_frame_t.frame_index` | 帧序列号 | 连续递增 |
| `temporal_frame_t.reset_history` | 重置历史缓存标记 | 场景切换、传送或镜头突变时置为非 0 |
| `temporal_frame_t.camera_near/far/fov_y` | 相机投影参数 | 近远平面距离、垂直视场角（弧度制） |
| `temporal_frame_t.reactive` | 可选响应遮罩（Reactive Mask） | 调用方提供或由库内部派生 |
| `temporal_frame_t.transparency` | 可选透明度/合成遮罩 | 调用方提供或由库内部派生 |

### 5.2 Vulkan 时域接入示例

```c
#include "mc_interface.h"
#include <string.h>

static void *g_temporal_vk = NULL;

int temporal_vk_init(VkPhysicalDevice phys, VkDevice dev, unsigned int in_w, unsigned int in_h)
{
    input_param_t p;
    memset(&p, 0, sizeof(p));
    p.struct_size = (uint32_t)sizeof(p);
    p.input_type = INPUT_TEXTURE_RGB8Unorm;
    p.width = in_w;
    p.height = in_h;
    p.scaler_factor = 2.0f;              /* 必须在 (1.0, 8.0] 范围内 */
    p.alg_mode = TEMPORAL_SPEED_MODE;    /* 或 TEMPORAL_BALANCED_MODE */
    p.backend = MAGIC_BACKEND_VULKAN;
    p.log_level = MAGIC_LOG_ERROR;
    p.gpu_context.physical_device = phys;
    p.gpu_context.device = dev;
    /* 创建期可选：p.depth_reversed / p.depth_infinite / p.hdr_color */

    /* 首次调用创建 g_temporal_vk 句柄 */
    return MC_Enable(&g_temporal_vk, NULL, &p, NULL);
}

int temporal_vk_process(VkCommandBuffer cmd,
                        uint64_t color_img, uint64_t depth_img, uint64_t motion_img,
                        uint64_t output_img,
                        uint32_t color_fmt, uint32_t depth_fmt, uint32_t mv_fmt, uint32_t out_fmt,
                        uint32_t color_layout, uint32_t depth_layout, uint32_t mv_layout, uint32_t out_layout,
                        unsigned int frame_index, int reset_history)
{
    if (!g_temporal_vk) return -1;

    temporal_frame_t tf;
    memset(&tf, 0, sizeof(tf));
    tf.struct_size = (uint32_t)sizeof(tf);
    tf.depth.handle.vk_image = depth_img;
    tf.depth.format = depth_fmt;
    tf.depth.layout = depth_layout;
    tf.motion.handle.vk_image = motion_img;
    tf.motion.format = mv_fmt;
    tf.motion.layout = mv_layout;
    tf.jitter_offset_x = 0.0f;           /* 输入像素单位，+X 向右 */
    tf.jitter_offset_y = 0.0f;           /* 输入像素单位，+Y 向下 */
    tf.motion_vector_scale_x = 0.0f;     /* (0,0) 默认对应 UV 归一化运动向量 (in_w, in_h) */
    tf.motion_vector_scale_y = 0.0f;
    tf.frame_index = frame_index;
    tf.reset_history = reset_history;
    tf.camera_near = 0.1f;
    tf.camera_far = 1000.0f;
    tf.camera_fov_y = 1.0f;              /* 垂直 FOV（弧度） */
    tf.view_to_meters = 1.0f;
    tf.frame_time_delta_ms = 16.67f;

    magic_frame_t frame;
    memset(&frame, 0, sizeof(frame));
    frame.image_in.handle.vk_image = color_img;
    frame.image_in.format = color_fmt;
    frame.image_in.layout = color_layout;
    frame.image_out.handle.vk_image = output_img;
    frame.image_out.format = out_fmt;
    frame.image_out.layout = out_layout;
    frame.frame = &tf;
    frame.command_buffer = cmd;          /* 必须处于录制状态 */

    output_status_params_t status;
    return MC_Enable(&g_temporal_vk, &frame, NULL, &status);
}

void temporal_vk_shutdown(void)
{
    if (g_temporal_vk) {
        MC_Disable(g_temporal_vk);
        g_temporal_vk = NULL;
    }
}
```

### 5.3 后端资源与同步约定

| 后端 | 平台 | `input_param_t.gpu_context` | `magic_frame_t.command_buffer` | 资源联合体成员 |
|------|------|-----------------------------|--------------------------------|----------------|
| Metal | iOS / macOS | `device`（可选，空则使用默认系统设备） | 可选 `MTLCommandBuffer` | `pointer`（`MTLTexture*`） |
| Vulkan | Android / Windows | `physical_device` 与 `device` **必填** | **必须为正在录制的 `VkCommandBuffer`** | `vk_image`（`VkImage`） |
| Direct3D 11 | Windows | `device` **必填**（`device_context` 可选） | 不使用（传 `NULL`） | `pointer`（`ID3D11Texture2D*`） |
| OpenGL 4.3 | Windows | 调用线程当前上下文；库不主动切换 | 不使用（传 `NULL`） | `gl_texture`（`GLuint`） |
| OpenGLES | Android | 调用线程当前上下文；库不主动切换 | 不使用（传 `NULL`） | `gl_texture`（`GLuint`） |

**资源权属与同步注意事项：**
- **调用方持有权**：外部纹理、深度缓冲、运动向量及命令缓冲均归调用方管理，SDK 不主动销毁外部对象；SDK 仅管理自身的历史纹理、临时缓冲及计算管线。
- **Vulkan 命令录制**：SDK 仅将计算指令录入传入的 `command_buffer`，绝不自行调用 `vkBeginCommandBuffer`、`vkEndCommandBuffer`、`vkQueueSubmit` 或 `vkQueueWaitIdle`。
- **布局要求**：在 Vulkan 下，传入的 `magic_resource_t.layout` 必须为当前真实的图像布局，传 `VK_IMAGE_LAYOUT_UNDEFINED` 会被拒绝。

### 5.4 运动向量、深度与遮罩处理

- **运动向量（MV）**：定义为**当前帧像素指向历史帧对应像素的位置偏移**。SDK 绝不自动取负，方向规范为 +X 向右，+Y 向下。
- **MV 缩放系数 (`motion_vector_scale_x/y`)**：若传入 `(0,0)`，默认将归一化 UV 运动向量按 `(input_width, input_height)` 转换为像素单位；若存储已是像素位移，请传入 `(1.0, 1.0)`。
- **深度缓冲**：必须为 GPU 设备深度 `[0, 1]`。若采用 Reverse-Z 或无限远平面，请在初始化时配置 `param.depth_reversed` 与 `depth_infinite`。
- **遮罩自动派生**：当调用方未绑定 `reactive` 或 `transparency` 时，库内部会自动进行近似派生；若传入了显式纹理，则显式输入优先级最高。

## 7. 状态查询与常见错误排查

### 7.1 读取执行状态

在调用 `MC_Enable` 时传入 `output_status_params_t` 结构体指针以获取耗时与指标：

```c
output_status_params_t status;
int ret = MC_Enable(&handle, &frame, NULL, &status);
if (ret == 0) {
    printf("GPU 耗时: %.2f ms, 错误码: %u\n", status.gpu_time, status.error_code);
    if (status.temporal_status_valid) {
        printf("时域最近成功帧号: %u\n", status.temporal_frame_index);
    }
}
```

### 7.2 常见错误码对照

| 错误数值 | 宏定义 | 原因分析与解决方法 |
|----------|--------|--------------------|
| `-100001` | `MC_ERROR_INIT_NULL_PARAM` | 首次初始化时（`*handle == NULL`）传入了 `param == NULL`。 |
| `-100004` | `MC_ERROR_INIT_SCALER_OUT_OF_RANGE` | 缩放倍率超出范围（空域需在 `[1.0, 8.0]`，时域需在 `(1.0, 8.0]`）。 |
| `-100008` | `MC_ERROR_INIT_BACKEND_UNAVAILABLE` | 请求的渲染后端未编译进当前平台库。 |
| `-100025` | `MC_ERROR_INIT_GPU_CREATE_FAILED` | 创建 GPU 设备失败（例如缺少 `gpu_context` 中的设备指针）。 |
| `-100029` | `MC_ERROR_INIT_MODEL_FILE_OPEN_FAILED` | 无法打开模型文件（请检查 `param.model_path` 路径及文件权限）。 |
| `-101001` | `MC_ERROR_PROCESS_NULL_HANDLE` | `MC_Enable` 传入的 `handle` 为空或 `*handle == NULL`。 |
| `-101002` | `MC_ERROR_PROCESS_HANDLE_CORRUPTED` | 句柄内存完整性校验失败（句柄可能被非法篡改或已被释放）。 |
| `-105001` | `MC_ERROR_TEMPORAL_NULL_FRAME` | 时域模式下 `frame->frame` 指针为空。 |
| `-105003..6` | `MC_ERROR_TEMPORAL_MISSING_*` | 时域必需的颜色、输出、深度或运动向量句柄未正确赋值。 |
| `-105017` | `MC_ERROR_TEMPORAL_COMMAND_BUFFER` | Vulkan 时域未传入正在录制中的有效 `VkCommandBuffer`。 |

## 8. 从旧版本迁移指南

如果您正在从 v1.x 或 v2.0 升级：
1. **单一静态库**：移除对 `libmagic_sr_enable.a` 或 `libmagic_enable_sr.lib` 的引用，仅链接 `libmagic_sr.a`（Windows 为 `libmagic_sr.lib`）。
2. **单一公共头文件**：移除 `#include "mc_enable.h"`，统一使用 `#include "mc_interface.h"`。
3. **收敛 API 调用**：
   - 将原先独立的 `MC_Init(...)` 与 `MC_Process(...)` 统一替换为 `MC_Enable(&handle, &frame, &param, &status)`。
   - 将 `MC_Uninit(...)` 替换为 `MC_Disable(handle)`。
   - 删除已废弃的结构体 `control_param_t` 及命令枚举 `cmd_params_e`，参数动态重置只需在 `MC_Enable` 中传入修改后的 `param`。
4. **版本验证**：通过 `MC_GetVersion()` 确认版本返回字符串为 `"v2.1.0"`。
